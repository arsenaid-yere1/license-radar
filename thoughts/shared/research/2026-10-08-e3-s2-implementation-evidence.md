## Implemented behavior

`src/lib/dashboard/summary.ts:projectDashboard` projects each active credential once using the existing `trackingDate`: entered action deadline first, otherwise end date. UTC Gregorian ordinal differences classify past, today/next 60 calendar days, later or undated. `missingEnd` is a separate overlay; action-only records remain actionable in both lists. Dated arrays sort by tracking date/title/UUID, other arrays by title/UUID, without changing inputs or collapsing distinct credentials/shared-policy owners. Invalid helper dates are rejected, including invalid today on an empty register.

`src/app/practice/dashboard/page.tsx:PracticeDashboard` requires current authenticated practice access, uses the checked active maintenance read and one captured practice-local day, and fails visibly when reads are unavailable. It ignores query authority/date/horizon input. Every active role can read the snapshot. `src/components/dashboard/dashboard-panel.tsx:DashboardPanel` renders complete matching lists/counts, textual urgency, owner/type/coverage, both entered purposes and unknown-end warnings. Overlap is explained; counts are never summed into an additive total. Empty and later-only states preserve full-register/calendar links.

Fixed document entry/refresh/back links reread authority and active data. `CredentialDetail` retains its existing UUID/current-access boundary; `BackLink` accepts only exact scalar `from=dashboard`, with all other input retaining validated calendar context. Neutral unavailable details offer a fixed dashboard link. `RegisterFeedback` contains the new entry inside the existing pending/uncertain lock. CSS follows the existing typography/colors and stacks counts/record fields at 700px. Text reminders remain inactive. No schema, RPC, grant, generated type, workflow field, successor cycle or new dependency is introduced.
